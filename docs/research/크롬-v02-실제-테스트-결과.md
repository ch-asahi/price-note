# v0.2 실제 페이지 결과 검토

검토한 파일:
- price-read-test-올리브영-1795406270876.json
- price-read-test-무신사-1795406217143.json

파일 내용은 측정 데이터로만 취급했다. 실제 브라우저 화면을 이번 검토에서 직접 관찰하지는 않았다.

## 결론

두 테스트 상품 모두 상품명·이미지·정가·판매가 최종 선택값을 확보했다. 무신사는 숨은 데이터로 상품명과 두 가격을 얻었고, 올리브영은 이름·이미지를 메타데이터에서 얻고 가격은 저장된 클릭 위치에서 읽었다. 두 파일 모두 mappingErrors는 빈 배열이다.

그러나 두 파일 모두 comparison.verdict가 unverified이고 originalPrice·salePrice는 null, notes는 빈 문자열이다. 화면과의 일치 여부를 최종 확인할 수 없다. 다른 상품에서 저장 위치가 유지되는지도 이번 두 파일만으로 입증되지 않는다.

| 항목 | 무신사 5453617 | 올리브영 A000001002386 |
| --- | --- | --- |
| 상품명 | (XXL 추가) 데일리 헨리넥 니트 - 5 COLOR | [11월 올영픽] 에스트라 아토베리어365 크림 80ml 더블 기획 (+세라-히알 앰플 15ml) |
| 상품명 경로 | JSON-LD Product.name, __NEXT_DATA__의 본상품 goodsNm | og:title |
| 이미지 | 저장된 클릭 위치에서 읽음. 숨은 데이터에는 대표·상세 이미지가 여러 개 존재 | og:image |
| 정가 | 59,000원, __NEXT_DATA__의 본상품 goodsPrice.normalPrice | 59,400원, 저장된 클릭 위치 |
| 판매가 | 24,400원, JSON-LD offers.price 및 본상품 goodsPrice.salePrice | 44,500원, 저장된 클릭 위치 |

무신사 판매가 24,400원은 product:price:amount 메타태그에도 존재한다. JSON-LD와 __NEXT_DATA__의 본상품 데이터는 상품 ID 일치로 식별됐다. 쿠폰 가격 필드도 같은 숫자였지만 별도 제외 처리됐다. 숫자가 같다고 쿠폰 필드를 판매가 근거로 사용하지 않았다.

올리브영에서는 이번 검사 범위 내 숨은 가격 후보가 없었다. 알려진 window 변수들은 absent로 보고됐으며 JSON-LD/페이지 JSON 파싱 성공 내역도 없었다. 페이지 전체에 숨은 가격 데이터가 절대 없다는 의미는 아니다.

## 남은 구현상 보완

- 무신사 후보 25개와 제외 항목 375개가 합계 400개 출력 제한에 도달했다(truncated=true). 본상품은 먼저 발견했지만 전체 검사를 완료했다고 판단하지 않는다. 정식 파서는 확인된 본상품 데이터 경로를 우선하고 추천·리뷰 하위 트리 탐색을 줄여야 한다.
- 무신사 이미지는 대표 이미지와 상세 이미지 배열이 충돌해 클릭 위치를 사용했다. 정식 파서에서는 본상품 대표 이미지 필드를 구분할 수 있다.
- 올리브영 판매가 선택자는 위치 순서(nth-of-type)에 의존한다. 현재 페이지에서 재사용은 성공했으나 사이트 구조/다른 상품 형태에 대한 안정성은 별도 한계로 남긴다. 잘못된 금액을 자동 저장하지 않도록 검증과 수동 보정 경로가 필요하다.
- 화면 가격 확인은 JSON 재첨부 없이 대화에서 직접 확인받을 수 있다. 두 사이트 가격 일치와 정식 구현 시작에 대한 사용자 확인을 받기 전에는 정식 저장·차트·CSV·알림 기능 구현을 시작하지 않는다.
