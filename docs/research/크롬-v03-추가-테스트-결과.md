# v0.3 추가 테스트 결과 검토

## 입증된 동작

- 네 상품 모두 상품명·이미지·정가·판매가 값을 확보했고 mappingErrors는 빈 배열이다.
- 올리브영 두 상품 모두 이전 상품에서 저장한 것과 같은 정가·판매가 CSS 선택자로 값을 읽었다. 다른 상품에서 위치를 재사용한 증거다. 화면 일치를 확인했다는 증거는 아니다.
- 무신사 추가 두 상품도 JSON-LD와 __NEXT_DATA__에서 같은 판매가를 읽었다.
- 팀버랜드 상품은 정가와 판매가가 같은 값이었다. 옵션 가격 목록의 값들도 관측된 후보에서 같은 값이었으나, 첫 번째 실제 옵션의 순서와 사용자 선택은 확인되지 않았다.

## 아직 확인되지 않은 항목

네 파일 모두 comparison.verdict=unverified, 화면 정가·판매가=null, 메모는 비어 있다. basis의 priceKind·loginState·optionCase는 모두 unknown, firstOptionConfirmed=false이다. 결과의 priceBasisChecksPassed도 모두 false다.

따라서 다음을 별도로 확인해야 한다.
- 읽은 네 가격이 화면과 일치하는지, 쿠폰·등급·카드 할인을 뺀 공통 할인가인지
- 옵션이 있으면 첫 번째 상품 옵션으로 읽었는지, 옵션별 가격 차이가 있는지
- 로그인 상태(미확인으로 두는 것도 가능하며 로그인 영향이 없다고 해석하지 않음)
- 올리브영 세일 없는 상품에서 정가가 없거나 가격 표시 레이아웃이 달라져도 잘 읽는지. 추가 두 파일은 모두 정가보다 낮은 가격으로 읽혀 이 경우를 검증하지 못했다.

무신사는 두 파일 모두 숨은 데이터 출력 제한에 도달했다(truncated=true). 본상품 값은 확보했지만 전체 탐색 완료라고 주장할 수 없다. 본상품 데이터 경로 우선과 추천/리뷰/큐레이션 하위 트리 제외가 보완 대상으로 남아 있다.

## 진행 상태

### 대화에서 추가 확인된 사항

- 네 상품 모두 비로그인 상태에서 테스트했다.
- 사용자가 네 상품의 판매가는 쿠폰·회원등급·카드 할인을 제외한 가격이라고 확인했다.
- 바른생각 상품은 옵션별 가격이 달랐고, 읽은 판매가 8,500원은 첫 번째 옵션 가격이라고 확인했다. 이 상품은 '옵션 가격 다름'으로 표시한다.
- JSON 원본의 미확인 필드를 임의로 수정하지 않고 대화 확인을 별도 증거로 남긴다. 다른 상품의 옵션 가격 차이 여부는 추정하지 않는다. 로그인 전후 차이도 미확인이다.
- 남은 필수 테스트 사례는 올리브영의 세일 없는 상품 1개다. 이를 확인한 뒤 조건부 승인에 따라 정식 구현을 진행한다.

읽기와 저장 위치 재사용 및 위 대화 확인 사항을 반영했다. 올리브영 비할인 상품 검증은 미완료다. '추가 테스트 통과 시 정식 구현'이라는 사용자의 조건부 승인은 유효하다. 통과 여부가 확인되면 추가 승인 질문 없이 구현한다. 현재는 정식 구현을 시작하지 않는다.

사용자가 대화에서 화면 가격과 옵션을 확인해 주어도 되며, 같은 검사를 다시 하고 파일을 재첨부할 필요는 없다. 올리브영 비할인 상품에 대해서만 미검증 사례를 추가하면 된다.
