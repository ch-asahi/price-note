# 상품 가격 추이 사이트 사전 테스트

검사일: 2026-11-23 (한국 시간)

## 방법

- curl의 일반 HTTPS GET 요청을 사용했다. 브라우저 실행, 로그인, 사용자 에이전트 위장, 프록시, 캡차 풀이를 사용하지 않았다.
- 기본 제한 환경에서는 DNS 조회가 실패하여, 네트워크 접근 권한으로 동일한 일반 요청을 실행했다.
- 각 사이트 robots.txt 및 상품 페이지를 각각 한 번씩 요청했다. 사이트별 요청 간격은 5초 이상이었다.
- 응답 HTML에서 JSON-LD → og 메타태그 → 페이지 내 JSON 순으로 검사했다.

## 결과

| 사이트 | 테스트 상품 URL | 상품 응답 | robots.txt 응답 | 추출 결과 |
| --- | --- | --- | --- | --- |
| 무신사 | https://www.musinsa.com/products/2411190 | 403, Cloudflare 차단 HTML | https://www.musinsa.com/robots.txt : 403 | 상품명·이미지·정가·판매가 모두 추출 불가 |
| 올리브영 | https://www.oliveyoung.co.kr/store/goods/getGoodsDetail.do?goodsNo=A000000181997 | 403, Cloudflare challenge HTML | https://www.oliveyoung.co.kr/robots.txt : 403 | 상품명·이미지·정가·판매가 모두 추출 불가 |

두 응답 모두 JSON-LD 0개, og 메타태그 0개, application/json 또는 __NEXT_DATA__ 스크립트 0개였다. 그 밖의 스크립트는 차단 페이지용으로, 상품 데이터가 아니었다. 상품 자체가 없거나 모든 환경에서 추출 불가능하다는 뜻은 아니며, 이번 요청 환경에서 실제 상품 HTML을 받지 못했다는 결과다.

robots.txt 본문도 규칙 텍스트가 아닌 차단 HTML이므로 수집 허용 여부는 확인하지 못했다. robots.txt가 없거나 수집을 허용한다는 의미로 해석하지 않는다.

## 확인받을 구현 방향

사용자가 지정한 403 처리 규칙에 따라 두 쇼핑몰 모두 수동 입력으로 처리한다. URL을 붙여넣고 상품명, 이미지 주소(선택), 정가, 판매가를 직접 입력해 등록하고, 이후 오늘 가격도 직접 입력한다. 미입력 날짜는 빈칸으로 유지한다.

Next.js, Vercel, Supabase, GitHub Actions 구조는 요청대로 준비할 수 있다. 다만 현재 두 사이트에 대한 자동 가격 수집은 비활성화해야 하므로, 스케줄을 설정해도 이 두 사이트 가격이 자동으로 쌓이지는 않는다. 사이트별 파서 파일과 수집 실행 구조는 향후 일반 HTTP 및 robots.txt 확인이 가능한 쇼핑몰을 추가할 수 있도록 분리할 예정이다.

그래프, 정가·판매가 기록, 통계, 판정 배지는 수동으로 기록한 데이터에도 적용한다. 사이트 구현은 이 결과에 대한 사용자 확인을 받은 뒤 시작한다.
