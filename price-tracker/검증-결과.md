# 가격노트 1.0 검증 결과

**1.1 후속 상태:** 사용자가 1.0의 실제 가격 기록 정확성을 확인했다. 요청한 화면·행사명·표시 규칙 변경과 새 CSV 호환을 구현했고, 새 검증 내용은 `업데이트-1.1.md`를 따른다. 아래의 실제 설치 미확인 내용은 1.0 개발 당시의 기록이다.

## 실제 사전 테스트에서 확인한 사항

- 사용자가 Chrome에서 연 무신사 상품에서 JSON-LD와 __NEXT_DATA__의 본상품 정가·판매가를 확보했다.
- 올리브영 여러 상품에서 저장한 가격 선택자를 재사용했다.
- 사용자 대화로 추가 네 상품이 비로그인 공통 판매가였음을 확인했다.
- 바른생각 상품은 옵션별 가격이 달랐고 8,500원이 첫 번째 옵션 가격이었다.
- 올리브영 ENHYPEN 상품은 별도 정가 없이 판매가 85,500원만 표시됐다고 확인했다. 정가/판매가 동일 요소 중복을 거부하도록 수정했다.

이 확인을 근거로 사용자의 '추가 테스트 후 정식 구현' 조건에 따라 구현했다. 화면 비교란이 비어 있던 원본 JSON 자체를 사후 조작하지 않았다.

## 자동 검증

JavaScript 구문과 manifest/참조 파일 검사를 실시했다. Node.js 기본 라이브러리만 사용하는 테스트로 다음을 검증한다.

- 허용 URL과 상품 ID 정규화, 추적 쿼리 제거
- 한국 날짜 경계, 날짜 오류 거부
- 날짜당 한 건, 최신 시각 우선, 정가 null 유지
- 14개 날짜·직전 90일 중앙값의 10% 기준, 최저가·평균가
- 미기록 날짜 통계 제외 및 SVG 선 끊김
- 옵션 불확실 시 자동 기록 보류, 다른 옵션 가격의 숨은 기본가 미사용
- 메타·JSON-LD·페이지 JSON·전역 변수, getter/페이지 코드 미실행
- 쿠폰·단위 가격·배송·다른 상품·리뷰 데이터 제외
- 옵션 가격 표를 기본 가격과 섞지 않고 차이 여부만 수집
- 별도 정가 근거 및 동일 화면 요소 중복 거부
- CSV의 한글·쉼표·따옴표·줄바꿈·수식 접두어·정가 빈칸·선택자 왕복
- 잘못된 CSV·음수 가격·미래 날짜·50개 초과 거부
- CSV 중복 병합 시 기존 최신 기록 유지
- Chrome API 모의 환경에서 동시 등록/기록 직렬 처리
- 허용되지 않은 발신자·옵션 상태 거부
- 같은 날 로그인 전후 가격 차이 보관
- 같은 한국 날짜 저녁 알림 중복 방지와 미기록 상품만 열기

Chrome API 모의 테스트는 실제 브라우저 설치나 OS 알림 테스트를 대체하지 않는다.

## 확인하지 못한 부분

내장 브라우저는 로컬 미리보기에 연결하지 못했다. Windows Chrome 조작 도구도 현재 URL을 확신하지 못해 정책상 UI 조작을 중단했다. 다른 브라우저 자동화 경로로 우회하지 않았다.

따라서 실제 설치 후 페이지 버튼, 팝업의 시각적 배치, Windows 알림 표시, 실제 사이트 옵션 UI의 최종 동작은 사용자 확인이 필요하다. 설치와-사용법.md의 마지막 확인 순서를 제공한다.

## 의도된 제한

서버·추가 HTTP·프록시·캡차 풀이·자동 로그인·자동 옵션 클릭·계정 관심상품 연동은 없다. 미방문 날짜는 빈칸이며, 옵션을 확실히 확인하지 못하면 자동 기록을 보류한다. 사이트 구조 변경을 영구적으로 견딘다고 보장하지 않는다. 원격 상품 이미지는 추가 요청을 피하기 위해 주소만 보관한다. 원본 가격 이력은 local storage에 있고 CSV로 백업한다.
